## A. 30 秒解释题

### 1. 为什么换一个更强的 Model，仍不能自动获得文件读取、命令执行和跨轮状态？

<details>
<summary>参考答案</summary>

因为这些职责由 Harness 中的不同能力拥有，而不是模型权重的一部分。模型调用接收 messages 与 tool schemas，产生文本或 tool call；Filesystem、Tools、Session、Sandbox 分别由对应 package/provider 提供。

更强的 Model 可能更会选择动作，却不会凭空创造操作系统权限、工具实现、状态日志和安全策略。

证据：[`dsh-llm`](https://github.com/deepseek-ai/deepseek-harness/tree/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/llm/llm)、[`dsh-tools`](https://github.com/deepseek-ai/deepseek-harness/tree/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/tools)、[`dsh-session`](https://github.com/deepseek-ai/deepseek-harness/tree/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/session)、[`sandbox`](https://github.com/deepseek-ai/deepseek-harness/tree/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/sandbox)。

</details>

### 2. “Agentic System ≈ Model + Harness”为什么只能作教学近似？

<details>
<summary>参考答案</summary>

它能说明完整系统需要“推理中心 + 运行支撑”，但源码中的 `Agent` 是更具体的运行对象。`dsh-agent` 拥有 Agent handle、live registry 和 `agent/*` 事件，默认创建和驱动逻辑由 `dsh-agent-loop` 提供。

因此不能把该公式写成源码 `Agent` 接口定义。

证据：[`packages/core/agent/README.md`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/agent/README.md)。

</details>

## B. 比喻校准题

### 3. 补全并指出边界

| 工作室对象 | 对应概念 | 比喻在哪里失效 |
|---|---|---|
| 模块轨道 | ？ | ？ |
| 设备 | ？ | ？ |
| 操作手册 | ？ | ？ |
| 工作日志 | ？ | ？ |

<details>
<summary>参考答案</summary>

| 工作室对象 | 对应概念 | 比喻边界 |
|---|---|---|
| 模块轨道 | Cordis Context、依赖和生命周期 | Cordis 不是 OS，也不存在物理插槽顺序 |
| 设备 | Tool / 外部 capability | 有 tool schema 不等于动作必然获准或成功 |
| 操作手册 | Skill | Skill 是可复用指令，不是执行能力本身 |
| 工作日志 | Session event log | Session 不只是聊天消息数组，也不等于 persistence provider |

</details>

### 4. Cordis Context 与 Spring `ApplicationContext` 有什么相似和不同？

<details>
<summary>参考答案</summary>

相似：都帮助组织依赖、生命周期、服务发现和扩展，消费方不必直接构造具体实现。

不同：Cordis 有自己的 Plugin、Fiber、Service、typed event 与 reversible effect 语义；Service Definition 还拥有稳定 `ctx.<key>` 和词汇，不能直接等同于 Java interface 或 Spring Bean 定义。

</details>

## C. 机制与预测题

### 5. 把 LLM、Tools、Session、Agent Loop 都做成插件，主要解决什么问题？

<details>
<summary>参考答案</summary>

主要解决变化隔离和组合问题：不同 profile 可以装配不同插件，provider 可以在稳定 capability seam 后替换，插件还能参与统一依赖与生命周期。

它不保证任意插件可以无成本互换；契约、依赖、配置和行为兼容仍然存在。

</details>

### 6. 如果一个 Consumer 只依赖稳定的 `ctx.<key>`，替换 Provider 后理论上什么可以不变？什么仍需验证？

<details>
<summary>参考答案</summary>

理论上 Consumer 的调用位置与业务流程可以不变，因为它依赖稳定服务键和契约，而不是某个实现文件。

仍需验证：新 Provider 是否完整实现契约、是否满足依赖、生命周期是否兼容、错误和性能语义是否变化，以及配置是否正确加载。

</details>

### 7. 为什么 Session 不应该直接等同于数据库？

<details>
<summary>参考答案</summary>

Session 的核心职责是 append-only event log 和 derived model history；持久化是独立关注点。数据库可以是某种 persistence 实现，但不是 Session 概念本身。

证据：[`packages/core/session/README.md`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/packages/core/session/README.md)。

</details>

## E. 结论校准题

### 10. 改写过强结论：“Model 直接调用文件系统。”

<details>
<summary>参考答案</summary>

更准确：Harness 向 Model 提供模型可见的工具 schema；Model 可以返回 tool call。具体工具由 Harness 的 registry 与 guarded pipeline 调用相应 capability/provider，Filesystem 或 Sandbox 在模型外部执行并返回结果。

</details>

### 11. 改写过强结论：“YAML 中后写的插件一定最后启动。”

<details>
<summary>参考答案</summary>

更准确：YAML 行序和 patch stack 能提供配置组合证据，但插件实际激活还受 Cordis 依赖解析、`inject`、生命周期与运行条件影响。未检查 Loader/Fiber 或运行证据前，不能把文件顺序当成激活顺序。

</details>

### 12. 改写过强结论：“Sandbox 就是一个 Docker 容器。”

<details>
<summary>参考答案</summary>

更准确：本仓库的 Sandbox group 为 subprocess 执行提供策略约束和平台后端；它可能被更强隔离实现替换，但 generic sandbox icon 不能推断容器、microVM 或远程执行。

</details>
