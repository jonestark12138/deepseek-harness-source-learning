# 第 01 次：从“只有大脑”到可工作的 Agentic System

> 源码基准：[`cd5ef8148158c3a752a658978873241fdf8e2bbc`](https://github.com/deepseek-ai/deepseek-harness/tree/cd5ef8148158c3a752a658978873241fdf8e2bbc)
> 本讲定位：建立第一张源码地图，不追 Cordis、Agent Loop、Session 或 Sandbox 的内部实现。

## 这讲只解决一个问题

一个只会理解、推理和生成的 Model，怎样被组织成能够连接真实环境、保存过程并持续完成多步骤工作的 Agentic System？

先把结论压缩成一句话：

> **Model 负责“想”；Harness 负责把能力、状态、约束与下一步组织起来。**

这里的“Agentic System ≈ Model + Harness”是教学近似，不是 DeepSeek Harness 源码中 `Agent` 接口的定义。

## 学完后的可观察结果

不看教材，你应该能够：

1. 用自己的话区分 Model、Harness、源码中的 Agent 与 Agent Loop。
2. 解释为什么 LLM、Tools、Session、Agent Loop 自己也是插件。
3. 从 `apps/cli/src/bin.ts` 走到 `boot()`，并知道第一讲在哪里停下。
4. 区分 Tool 与 Skill、Session 与普通聊天数组、Sandbox 与“一个目录”。

## 概念预算

### 现在必须懂

- Model 是推理与生成中心，不是完整 Agentic System。
- Harness 组合上下文、能力、状态、策略和后续步骤。
- DeepSeek Harness 的核心能力也由 Cordis 插件组合。
- 第一次源码阅读先看入口和装配，不先钻进 Agent Loop。

### 知道存在即可

- Cordis Context、Service、Event、reversible effect。
- Tool、Skill、Session、Sandbox 的第一层职责。
- Profile、bundle、patch 的组合关系。
- `dsh-agent` 与 `dsh-agent-loop` 是两个不同职责的 package。

### 后续深入

- Cordis Fiber、依赖激活和完整生命周期。
- Service Definition / Provider / Consumer 的实现。
- Agent Loop 的 turn/step 状态机。
- Session 投影、持久化、压缩与恢复。
- 工具审批、安全策略与 Sandbox 后端。
