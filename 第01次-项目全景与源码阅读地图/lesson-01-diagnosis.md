# Lesson 01 教学诊断

> 诊断对象：`00-学习导航.md` 至 `04-分享稿.md`
>
> 源码基准：`cd5ef8148158c3a752a658978873241fdf8e2bbc`
> 本文只诊断，不修改旧教材正文。

## 结论

旧版第一讲的源码证据、阅读路线和结论边界整体可靠，但学习体验仍像“整理得很好的技术笔记”，没有真正成为帮助第一次学习者建立直觉的图文教材。

最主要的问题不是文字写错，而是同一套抽象关系反复使用 Mermaid 方框和箭头表达。五份材料合计 1,671 行、33 个 Mermaid 图块，却没有一张被 Markdown 引用的独立教学插图。读者能够逐段读懂，但难以在脑中留下稳定、有空间感的长期图景。

## 值得保留的部分

1. **入口链收得很窄。** `bin.ts -> profile-boot.ts -> base bundle -> boot()` 适合作为第一次源码阅读路线。
2. **证据边界意识很好。** 教材主动区分 YAML 能证明什么、不能证明什么，并提醒不要用文件顺序推断插件激活顺序。
3. **五份材料职责清楚。** 导航、课件、逐步讲解、练习、分享稿不应合并成一篇超长文章。
4. **练习不只考记忆。** 已经包含源码定位、过强结论修正和对外表达题，这些比单纯名词问答更有价值。
5. **版本可追溯。** 源码引用固定到完整提交，适合公开学习资料。

## 为什么仍然显得死板

### 1. 图很多，但视觉语言只有一种

`01-课件.md` 和 `02-逐步讲解.md` 各有 12 个 Mermaid，`04-分享稿.md` 又有 9 个。Model、Harness、Cordis Context、五层地图和入口调用链在不同文件中被重复画成近似的矩形节点。

这些图能整理信息，却很少利用空间隐喻、视觉焦点、语义颜色或固定形状帮助记忆。读者记住的是“这里有几个框”，而不是“Model 像工作室里的推理核心，Harness 是让它能接触真实世界并持续工作的完整安排”。

### 2. 课程过早同时打开太多概念

第一讲快速出现 Model、Harness、Agent、Agent Loop、Cordis、Context、Plugin、Service、Event、effect、profile、bundle、patch、五层源码地图和六个核心包。每个概念的解释都不算错，但第一次学习者很难判断哪些现在必须形成稳定理解，哪些只需知道存在。

重构后应明确分层：

- **现在必须懂**：Model 与 Harness 的职责差异；核心能力也通过插件组合；第一次源码路线。
- **知道存在即可**：Context、Service、Event、Tool、Skill、Session、Sandbox、profile、bundle。
- **后续深入**：Cordis 生命周期、Service Resolution、事件模式、Agent Loop 状态机、Session 与工具执行细节。

### 3. `Agent = Model + Harness` 容易成为错误记忆

这个公式适合解释广义 Agentic System，却不等于源码中的 `Agent` 接口。当前源码把 `Agent` handle、live registry 和 `agent/*` 事件放在 `dsh-agent`，具体创建和驱动由可替换的 `dsh-agent-loop` 提供。

重构后应写成：

> 教学近似：一个能持续工作的 Agentic System，大致由 Model 与 Harness 共同形成。

随后立即回到源码语言，解释 DeepSeek Harness 中的 `Agent` 是一个更具体的运行对象。

### 4. 比喻没有形成连续世界

旧版主要通过定义和职责表解释概念。虽然提到“能力集合”等直觉，但没有让 Model、Harness、Cordis、Plugin、Tool、Skill、Session 和 Sandbox 进入同一个可复用的空间模型。

重构应使用“模块化智能工作室”贯穿开篇：先进入工作室建立空间直觉，再把比喻拿掉，映射回正式架构和源码。比喻只负责进入概念，不代替真实机制。

### 5. 课件、讲解和分享稿重复生产相似图

三份材料都重新定义并重新绘制 Model/Harness、Everything is a Plugin 和入口链。维护成本高，也容易让同一概念出现细微差异。

重构后应建立六张共享主图。课件负责快速浏览，逐步讲解负责解释和源码映射，分享稿只复用其中最关键的三至四张。

### 6. 缺少可重复的视觉 QA

旧版 Mermaid 可以渲染，但没有统一的字体、颜色、形状和视口检查，也没有最终页面截图证据。现有 `model-agent-harness.svg` 已经比 Mermaid 更接近目标风格，但仍包含远程 Google Fonts，离线或 GitHub 渲染时可能发生字体和布局漂移。

## Mermaid 处理建议

| 旧图类型 | 处理 | 原因 |
|---|---|---|
| Model / Harness / Agent 关系 | 替换为 diagram-design | 需要比较、视觉焦点和职责边界，不只是流程 |
| Everything is a Plugin | 替换为 diagram-design | 需要展示从单体硬编码到插件组合的结构变化 |
| 五层源码地图 | 重构为 Source Reading Route | 当前更像目录分类，缺少“先看/略读/后看”的教学决策 |
| Cordis 生命周期状态图 | 从第一讲移除 | 过早进入后续课程机制 |
| `bin -> profile -> bundle -> boot` | 融入正式架构图和源码路线 | 避免同一调用链重复出现 |
| 一次 runtime 顺序 | 保留 1 张 Mermaid sequence | 顺序关系正是 Mermaid 的优势 |
| 自测完成检查图 | 删除 | 清单本身比流程图更清楚 |

## 重构后的叙事骨架

1. **真实问题**：只有一个聪明 Model，谁读文件、执行命令、保存过程并继续下一步？
2. **直觉对比**：Model Only vs Model + Harness。
3. **空间比喻**：进入“模块化智能工作室”。
4. **问题升级**：如果所有能力都写死在主循环里，会发生什么？
5. **插件化答案**：Everything is a Plugin。
6. **把比喻拿掉**：正式第一层架构。
7. **进入源码**：第一次只沿一条窄路径走到 `boot()` 边界。
8. **让静态地图动起来**：一张简化 runtime sequence。
9. **主动回忆**：解释、预测、画图和源码定位练习。

## 重构成功的判据

- 开篇 30 秒能说清 Model 与 Harness 的职责不同。
- 不看正文，也能用工作室比喻复述主要角色，并指出比喻的边界。
- 看正式架构图时不会把 Model 误认为 Tool、Session、Sandbox 的直接拥有者。
- 第一次打开源码时知道先看哪五个节点，以及为什么停在 `boot()`。
- Mermaid 不再承担概念海报和架构总览，只保留真正的顺序/状态表达。
