上一讲定了同一张工单：先查清运费边界错误，得到授权后修复并重新测试。本讲先完成诊断部分，暂不修改。我们要从“知道存在循环”，前进到能读懂请求、工具回执和步骤事件。

先读逐步讲解，再做实验与练习。视觉课件用四种图复盘同一条运行路径。预计正文与源码推演 45–60 分钟，实验与练习 30–45 分钟；不用一次完成，时间不是掌握标准。

本讲的工程验收

  • 用具体消息解释报告结果如何进入第二次请求，并说出调用关联号为什么必要。
  • 对正常、请求重试、读报告失败三种轨迹，预测步骤数、请求尝试数、工具调用数。
  • 在源码上指出外层步骤循环、内层请求重试、零步退出和结束候选的差异。
  • 运行本地可控循环，注入取消或新消息，用断言核对预测。
  • 解释固定脚本的适用范围，以及动态循环额外增加的预算、权限与验证责任。

实验只需 Node.js（JavaScript 运行环境），无需真实模型或密钥。公开阅读版在练习页内嵌完整实验脚本，不依赖私有制作库和源素材。

不在本讲硬塞的内容

第四讲展开工具批次调度和动作准入；第五讲展开会话事件到消息的派生；第八讲展开取消后恢复与外部结果未知；第九讲展开上下文压缩；第十五讲展开请求错误处理链。它们不是可忽略的细节，而是已经登记去向的后续核心机制。

第02讲 · 四张图拆开同一次排查

这些图不替代正文的源码和实验。看图时先回答图题，再沿箭头说明输入与返回，不把“看懂颜色”当成理解机制。

1. 时序：报告结果不能停在工具出口

模型提出调用；执行器产生回执；循环保存回执并准备下一步输入。同一步可以提出两次读取。图中调用号是简写，具体协议见正文。

2. 故障对照：重拨电话不等于进入下一阶段

只改变首个请求的前两次尝试。三步仍是三步，请求尝试变成五次。别把请求重试画成工具重放。

3. 流程：结束候选不等于业务成功

这张图从完整响应之后开始，省略初始准入和错误恢复。输出上限、无工具调用、工具给出结束结论是不同分支；外层仍要检查新输入。

4. 场景：新材料先放收件盘

已经发出的请求不会自动更新。下一步准入领取新消息。执行授权仍是独立的门禁，不是盘里的一张提醒。

逐步讲解

第02讲 · 把一次回答接成一段可追踪的工作

源码基线：cd5ef8148158c3a752a658978873241fdf8e2bbc。本讲区分源码事实、纸面推演、已执行教学循环和已执行上游局部测试。没有调用真实模型，也没有把模拟运费计算说成 Java 实测。

一、报告读完了，可排查为什么还没往下走

接着第一讲。用户给出的任务是：“先查清运费边界测试失败原因，不要修改。”现在有三份可能用得上的材料：失败报告写着输入 10000 分、预期运费 0、实际 800；业务约定写着“满 10000 分免运费”；实现却是 return orderCents > 10000 ? 0 : 800;。但是，材料存在于工作区，不表示模型已经看见。

假设第一次请求只带了任务和读取工具的说明。模型提出“读报告”，执行器读到了失败报告，然后函数返回。到这里，程序做成了一次读取，却没有做成一次排查。缺少的不是更聪明的一句提示，而是有人把刚读到的证据送回模型，让它继续判断是否需要约定与源码。

Agent Loop（智能体循环）就是这套接力机制：准备输入 → 请求模型 → 处理输出中的工具调用 → 保存结果 → 按条件继续。像排查事故时的值班协调员：开发者判断要看什么，协调员安排受控读取，把回执放到下一次讨论桌上。比喻里的人并不对应一个独立模型；这里的协调职责主要由确定性程序承担。

对 Java 后端工程师，关键区别是：普通服务常按固定调用链执行；智能体的下一项动作可以由模型根据反馈选择，但工具准入、结果关联、取消和停止仍由程序控制。动态的是判断，不是安全规则可以随意变化。本讲最终要能沿着一份报告，追到下一份请求，而不仅是记住“有个循环”。

二、先定清四个计数单位，否则日志会把人带偏

Turn（一轮）是一次被驱动的运行边界；Step（一步）是轮内一次步骤执行，包含模型交互及该步骤产生的工具处理；Request Attempt（请求尝试）是一次向模型服务发出的具体尝试；Tool Call（工具调用）是模型提出的一项结构化动作。一步可能有多次模型请求尝试，也可能在一次成功响应中提出多个工具调用。

可以把“一轮”想成这一张排查工单，“一步”想成一次新的判断阶段，“请求尝试”想成这一阶段拨通咨询电话的尝试次数。电话占线重拨，不等于已经进入下一个排查阶段；一次接通后要求查两份文件，也不等于接了两张工单。这个比喻只解释计数，不意味着模型请求没有费用或副作用。

本讲受控模型依据已有结果选择动作。它不是人工写死“先执行读报告，再执行读代码”：改变请求中已有的证据，它会改变选择。正常路径是：

步骤 本次请求已包含的证据 模型选择 执行后的变化
第 1 步 只有用户任务 读取报告 增加失败断言，尚不知是契约还是实现问题
第 2 步 任务＋报告调用及结果 读取约定、读取源码 增加“含等于”的约定与“大于”的实现
第 3 步 前面全部调用与结果 解释边界差异，不再调用工具 正常结束诊断轮次，仍等待修改授权

因此正常实验是 1 轮、3 步、3 次请求尝试、3 次工具调用。第二步同时提出两个读取，所以不能根据工具调用数量反推步骤数。真实模型可能合并读取，也可能需要更多步骤；这里固定的是可复现的教学条件，不是产品保证三步完成。

三、沿报告的身份，走完一次反馈闭环

从上往下是时间。实线表示请求或交付，虚线表示返回。图中调用号为了可读性简写为 r1（报告调用）、r2（约定调用）、r3（源码调用）；教学程序实际使用 read-report、read-contract、read-code。它们对应同三份材料。

先盯住报告这一次调用。教学协议做了明确简化，模型返回的是动作名、参数和调用标识：

// 教学协议，不是上游供应商的原始请求格式。
{ id: 'read-report', name: 'read', args: { file: 'report' } }

循环不是把这段文字直接当命令执行。它交给受控执行器，执行器返回读取是否成功、哪份文件、内容和内容摘要值。循环再追加一条工具消息：

{
  role: 'tool',
  callId: 'read-report',
  result: { ok: true, file: 'report',
    text: 'amount=10000 expected=0 actual=800 FAIL', hash: '…' }
}

callId 是调用关联号，像快递回执上的单号。没有它，在同一步有两次读取时，就可能把约定的结果贴到源码调用上。ok 是工具动作是否成功，不是测试是否通过：成功读到一份失败报告，完全可以是 ok: true。报告中的失败，属于被读取的业务证据。

下一次请求里的 messages（消息列表）带上先前用户任务、助手提出的调用和工具回执。受控模型发现报告已具备、约定与源码还缺，才选择后两个读取。注意数据方向：模型提出意图 → 循环派发 → 工具生成结果 → 会话保存 → 下一次模型请求消费。工具不直接“给模型加记忆”，磁盘也不会自动进入模型输入。

上游的对应关系在步骤实现里能连起来：this.step 接收准备好的提示装配；buildRequest 取 session.deriveMessages() 派生的消息构建请求；响应收齐后写入 assistant/message；executeToolCalls 执行调用、形成工具结果；未结束则让外层进入下一步。第五讲会拆会话如何派生消息，第四讲会拆执行器如何调度；此刻必须掌握的是这条返回路径，不必提前背所有内部字段。

四、源码里为什么有两层循环

现在带着具体值读源码。外层推进步骤，内层处理一次步骤的模型交互。若把两者混为一谈，很容易把服务繁忙后的重试画成“重新做整个任务”。

4.1 外层：先准入，再花一次步骤

外层先计算候选步骤号，再调用 preStep（步骤前准入）。这个调用决定当前待处理输入能否进入、最终领取哪些消息。以下是连续原文：

        const step = phase.step + 1
        const decision = await this.preStep(target, { turn, step })
        if (decision.kind === 'reject') {
          turnEnds = { kind: 'blocked' }
          return false
        }
        if (turnEnds && decision.messages.length === 0) break
        // A removed waking message or an enter decision rewritten to empty
        // still owns the initial turn boundary, but it spends no model call.
        if (phase.step === 0 && decision.messages.length === 0) {
          turnEnds = { kind: 'completed' }
          return false
        }
        signal.throwIfAborted()
        this.session.append('step/start', { turn, step })
        phase.step = step

代入初始值：已经受理一轮，phase.step = 0。如果准入返回拒绝，执行在写入步骤开始事件之前就返回，结果为 blocked（被阻止），步骤数为 0。若准入允许但最初消息被移除，消息数是 0，同样不花模型请求，但结果是 completed（正常结束）。两个分支都是零步，原因却不同。

再代入读报告后的状态：phase.step = 1，上一步返回的结束原因是空值，盘里也没有新增用户消息。此时不会命中“初始零步且消息为空”，也不会命中“已经结束且消息为空”。因为报告的工具结果已经在会话里，下一步有东西可消费，不能拿“没有新增用户消息”当成“模型没有新证据”。这是理解这段判断最重要的一次手工推演。

4.2 内层：重试并没有把步骤号加一

在单步函数内部，请求错误分支把失败交给扩展点决定。只有得到重试决定，才在内层继续；不是见到任何异常都无条件重来。

        signal.throwIfAborted()
        if (action?.kind !== 'retry') {
          throw new LlmError(finish.failure.message, finish.failure.code, finish.failure)
        }
        continue
      }

这里的 continue 回到单步内部的模型请求准备，不回到外层的步骤号递增。假设第一次模型请求连续遇到两次可恢复失败，第三次才成功提出读报告：仍是第 1 步，只是第 1 步有三次尝试。它们没有成功产出并执行三个报告读取。

教学循环把“限流、服务不可用可重试，最多三次”写成显式实验策略。上游则把是否重试交给请求错误处理链；其默认末端不是自动批准重试。模型请求重试也不能推广成工具重放策略：重发一次读取通常只增加成本，重发一次付款却可能多扣一次钱。后续讲执行、恢复时，要重新审查动作是否已发生，不能借用模型重试规则。

五、有结果之后，究竟由谁决定停

先看单步尾部原文：

      if (finish.kind === 'max-tokens') return { kind: 'max-tokens' }

      const toolCalls = message.content.filter(block => block.type === 'tool-call')
      if (toolCalls.length === 0) return { kind: 'completed' }
      const { concluded } = await executeToolCalls(
        this.loopCtx, turn, step, toolCalls, signal,
        context => this.inbox.splice('next-step', this.inbox.nextStep.length, 0, [context]),
      )
      return concluded ? { kind: 'completed' } : null
    }

null 在这里不是“工具执行失败”，而是“这一步没有给出结束结论”。报告已经回来了，还应带着报告再次判断。没有工具调用可以返回正常结束；工具执行也可能给出结束结论；输出达到上限则优先返回相应原因，不把未完整输出的动作继续执行。

图里的“标记完成”仍只是这一步交给外层的结束候选。外层末尾还要检查待处理输入，并在合适时机调用停止前钩子，再次检查是否有新输入。像协调员说“本次会议可以散了”，却发现门口刚送来一份紧急材料，就要先处理它，而不是机械地关门。

此外，输出上限具有黏性：一轮里某一步触及上限，后续普通完成不能把整体记录降格为毫无限制的完成。这和 Java 批任务保留部分失败标记相似：最后一个子任务成功，不足以抹掉之前的异常结果。

还有一个更重要的边界：completed（正常结束）描述的是运行控制，不是业务目标已经达成。本讲的正常路径只是诊断结束，没有授权、没有修改、没有重新测试，所以完整修复任务的验收仍为假。反过来，读取失败后如实报告缺证据，也可以正常结束这次交流。第十六讲会把运行状态与独立验收拆开。

六、运行中补充要求：到达、领取、执行并不是同一时刻

到这里已经能解释反馈，新的麻烦来了：模型正在处理第一步，你又补充“只读相关文件”。它会立刻出现在那个正在运行的请求里吗？不会凭空出现。

Inbox（待处理输入队列）像桌边收件盘。系统接收材料是一件事；步骤前准入领取材料是第二件事；构造请求并交给模型是第三件事。已经发出的请求不是一个会随聊天窗口自动更新的共享白板。

在教学实验中，我们在报告结果写入后注入新消息，检查第一份请求快照没有它，第二份请求有它。这验证的是“何时被下一次请求消费”，不是上游所有并发时机的完整仿真。上游还区分下一轮和下一步的领取目标，本讲先沿已经运行的一轮讲清下一步领取。

如果补充内容是撤回修改授权，更不能只往盘里放一句话，然后相信模型记得住。执行边界要在动作执行点独立检查。权限就像门禁，收件盘里的提醒只是通知，不是闸机。第四讲与第七讲继续解决这一点。

取消也不是一句“请停止”的普通业务文本。Abort Signal（取消信号）让运行路径在明确检查点抛出取消；正在等待的组件还需要配合传播。正文原文可看到请求前、流式块消费后、步骤末尾的检查。取消能阻止后续动作，但不能保证已经写入外部系统的动作自动回滚。教学测试在报告回执后取消，断言不再开始第二次请求，同时当前步骤仍留下结束事件。

七、把故事变成可检查的运行记录

先预测，再在教材制作库根目录执行下面的本地命令；公开阅读版读者可从练习页复制三个完整脚本到同一文件夹。需要 Node.js（运行 JavaScript 的程序环境）24 或兼容版本，不需要密钥、联网模型或付费服务。

node case/agent-loop.cjs normal
node case/agent-loop.cjs retry
node case/agent-loop.cjs missing-report
node --test case/agent-loop.test.cjs

观察输出的三处，而不是只看“通过”：requests（模型请求快照）解释它每次看见什么；events（事件轨迹）解释步骤和尝试何时开始；messages（消息记录）解释工具结果怎样关联。正常场景的请求步骤号是 [1,2,3]；注入两次可恢复错误后是 [1,1,1,2,3]；缺报告时第二步如实说明读取失败，不会继续假装拥有源码证据。

作者实际执行记录：教学循环 17 项测试通过；固定上游基线中请求错误、工具调用、取消三个文件共 62 项测试通过。上游测试使用可控替身，证明相应实现分支在测试条件下的行为；不是对真实模型、全部工具和生产环境可靠性的背书。

如果程序输出与表格不同，先核对代码版本、场景名和初始材料，不要改预期去“配平”。若步骤对但模型仍在猜，检查请求是否带了结果；若调用两次但只见一条回执，检查调用关联和调度；若服务失败就不断重跑，检查重试所在层与预算。这已经是一条可用的排障顺序。

八、为什么不干脆固定成三步脚本

本例的边界缺陷很简单，固定“读报告、读约定、读源码”确实可以实现，成本更低，也更易测试。智能体循环的价值在于下一次判断可以根据证据变化：报告已经给了明确位置，可能缩小读取范围；报告文件缺失，需要寻找生成报告的前置条件；原因不在实现，则不该执意打补丁。

代价也清楚：动态路径增加请求次数、超时和停止策略的复杂性，因此要有事件、预算、权限和独立验收。不是把所有程序都改成智能体，而是把需要判断的部分放进反馈循环，把必须可靠执行的约束留给确定性程序。第十一讲会把两者组合成工作流程。

完成本讲，应能不用背段落就解释三件事：报告结果怎样进入下一次请求；两次请求失败为什么不一定增加步骤；轮次结束为什么不能直接宣告修复成功。第三讲紧接着打开那份“请求信封”：究竟装哪些指令、历史、工具说明和证据，才能让循环继续时不再盲猜？

练习与答案

一、先准备一个不花模型费用的实验台

正常为 3 / 3 / 3，正常结束；两次可恢复失败为 3 / 5 / 3，正常结束；缺报告为 2 / 2 / 1，模型在第二步说明失败后正常结束；拒绝为 0 / 0 / 0，被阻止；移除初始消息为 0 / 0 / 0，正常结束；直接声称修好为 1 / 1 / 0，正常结束。六种场景的完整修复验收都是假，因为没有完成授权、修改和复测链条。

“缺报告仍正常结束”不是隐藏错误：工具消息明确带有失败结果，最终回答明确报告缺证据。正常结束只是本轮控制流收束，不能覆盖证据状态。

三、读轨迹：找出模型并没有看见的材料

在正常输出中比较三份 requests（请求快照）。第一份有报告内容吗？第二份有源码内容吗？第三份与第二份到底多了什么？

答案与排障意义

第一份没有任何工具结果。第二份有报告调用与回执，但还没有约定和源码的读取结果。第三份增加第二步的两次调用及各自回执。若第三份缺了源码结果，模型即使继续运行也不能依据那份代码判断；先查回执写入与请求派生，不要先怪模型不聪明。

四、源码预测：为什么第二步可以没有新用户消息

把外层变量代入 phase.step = 1、turnEnds = null、decision.messages = []。它会零步退出吗？改为 phase.step = 0 又如何？再把结束原因为正常完成，消息仍为空，又如何？

答案

第一种继续，因为不是初始步骤且没有结束候选；旧会话刚增加了工具结果。第二种命中初始空消息分支，不花请求。第三种命中已经结束且没有新消息的分支。三个条件看起来都“没有用户消息”，含义并不相同。请在正文源码逐个代入，不凭故事猜。

五、故障注入：取消和补充消息

现有测试覆盖“报告回执后取消”与“报告回执后追加限制”。先找对应断言，再解释为什么前者请求数为 1，后者的第一份请求没有新消息、第二份却有。把取消改成模型返回时才触发，已有测试还检查了什么？

答案

循环在后续请求或派发前检查取消。补充消息进入待领取队列，到下一步才加入新请求；旧快照不会被改写。模型即使忽略取消并返回工具调用，循环仍应在派发前挡住它。取消不是外部副作用回滚，测试只证明这里不会继续新动作。

六、有限改造：限制最多花两次模型尝试

不修改上游，只在你复制的教学循环中增加“整轮总请求预算为 2”。先预测正常场景将停在哪里；再写测试检查：读报告后又读到了约定和源码，但第三次模型请求尚未发出。预算结束不能伪装成完成。

参考设计与验收断言

整轮预算与单步重试预算是两层约束。总计数在每次调用模型之前递增，包含失败尝试；超过预算时返回独立原因，例如 request-budget。在本例中两次成功请求已经执行三次读取，第三步准备请求时发现预算用尽，因此没有最终模型解释。

至少断言总尝试为 2、工具结果为 3、结束原因不是普通完成、业务验收是假。再用“首个请求失败一次”检验失败也消耗预算，不能只统计成功请求。参考答案给出设计而不直接替你完成代码；这道题验收的是改造和测试能力。

// Deterministic teaching model. No LLM, real shell, network or Java execution.
const { createHash } = require('node:crypto')
const digest = text => createHash('sha256').update(text).digest('hex')
const ORIGINAL = 'return orderCents > 10000 ? 0 : 800;'
const FIXED = 'return orderCents >= 10000 ? 0 : 800;'
const CONTRACT = '满 10000 分免运费；否则 800 分；不得改测试预期。'
const baseline = () => ({ code: ORIGINAL, contract: CONTRACT, report: 'amount=10000 expected=0 actual=800 FAIL' })

class TeachingHarness {
  constructor(files = baseline(), persisted = []) {
    this.files = files
    this.log = structuredClone(persisted)
    this.allowed = false // A new live executor requires fresh authorization.
    this.view = null
    // Close incomplete calls as unknown outcomes, never rerun them on recovery.
    const settled = new Set(this.log.filter(e => e.type === 'result').map(e => e.data.callId))
    for (const event of [...this.log]) if (event.type === 'call' && !settled.has(event.seq)) {
      this.append('result', { callId: event.seq, ok: false, error: 'interrupted; external outcome unknown' })
    }
  }
  append(type, data) {
    const event = { seq: this.log.length, type, data: structuredClone(data) }
    this.log.push(event)
    return event.seq
  }
  grant() {
    this.allowed = true
    this.append('authorization', { scope: 'one boundary fix; preserve tests' })
  }
  async execute(name, args = {}) {
    const callId = this.append('call', { name, args })
    let result
    try {
      if (name === 'read') {
        if (!Object.hasOwn(this.files, args.file)) throw Error('file not found')
        const text = this.files[args.file]
        result = { ok: true, file: args.file, text, hash: digest(text) }
      } else if (name === 'patch') {
        if (!this.allowed) throw Error('modification not authorized')
        if (args.expectedHash !== digest(this.files.code)) throw Error('code changed; read again')
        if (this.files.code !== ORIGINAL) throw Error('patch target no longer matches')
        this.files.code = FIXED
        this.allowed = false
        result = { ok: true, changed: true, hash: digest(this.files.code) }
      } else if (name === 'test') {
        if (![ORIGINAL, FIXED].includes(this.files.code)) throw Error('unknown teaching implementation')
        const rows = [9999, 10000, 10001].map(amount => {
          const actual = (this.files.code === FIXED ? amount >= 10000 : amount > 10000) ? 0 : 800
          return { amount, expected: amount >= 10000 ? 0 : 800, actual }
        })
        result = { ok: true, simulated: true, codeHash: digest(this.files.code), rows,
          exitCode: rows.some(r => r.actual !== r.expected) ? 1 : 0 }
      } else throw Error('unknown tool')
    } catch (error) { result = { ok: false, error: error.message } }
    this.append('result', { callId, ...result })
    return structuredClone(result)
  }
  compact(summary, sourceSeqs) {
    if (!Array.isArray(sourceSeqs) || !sourceSeqs.length || sourceSeqs.some(i => !Number.isInteger(i) || !this.log[i])) throw Error('missing source')
    const selected = sourceSeqs.map(i => this.log[i])
    for (const event of selected) {
      if (event.type === 'call' && !selected.some(e => e.type === 'result' && e.data.callId === event.seq)) throw Error('unpaired tool call')
      if (event.type === 'result' && !sourceSeqs.includes(event.data.callId)) throw Error('unpaired tool result')
    }
    this.append('summary', { text: summary, sourceSeqs })
    this.view = { text: summary, sourceSeqs: [...sourceSeqs] }
  }
  snapshot() { return structuredClone(this.log) }
  verify() {
    const results = this.log.filter(e => e.type === 'result').map(e => e.data)
    const has = file => results.some(r => r.ok && r.file === file)
    const latestTest = results.filter(r => r.simulated).at(-1)
    return { complete: has('report') && has('contract') && has('code')
      && this.log.some(e => e.type === 'authorization')
      && results.some(r => r.ok && r.changed)
      && this.files.code === FIXED && latestTest?.codeHash === digest(this.files.code)
      && latestTest.exitCode === 0 && latestTest.rows.length === 3,
    boundary: 'Only this deterministic fixture; not Java or a real agent evaluation.' }
  }
}
module.exports = { TeachingHarness, baseline, ORIGINAL, FIXED, digest }

// Teaching loop, not an upstream reimplementation. No network, shell or paid model.
// A controlled model chooses actions from feedback; the driver never hardcodes their order.
const { TeachingHarness, ORIGINAL, FIXED } = require('./runner.cjs')
const clone = value => structuredClone(value)
const TASK = '先查运费边界测试失败原因，不要修改。'

class FeedbackModel {
  async generate(request) {
    const results = request.messages.filter(m => m.role === 'tool')
    const has = file => results.some(m => m.result.ok && m.result.file === file)
    const failure = results.find(m => !m.result.ok)
    if (failure) return { text: '读取失败，缺少证据；不猜测原因，不修改。', calls: [] }
    if (!has('report')) return { calls: [{ id: 'read-report', name: 'read', args: { file: 'report' } }] }
    if (!has('contract') || !has('code')) return { calls: ['contract', 'code'].filter(f => !has(f)).map(file => ({ id: `read-${file}`, name: 'read', args: { file } })) }
    const latest = file => results.filter(m => m.result.ok && m.result.file === file).at(-1).result.text
    const matches = latest('code') === ORIGINAL
      && latest('contract')?.includes('满 10000 分免运费')
      && latest('report')?.includes('amount=10000 expected=0 actual=800')
    if (matches) return { text: '报告：10000 得 800；约定包含等于，实现用了严格大于。原因已定位，等待修改授权。', calls: [] }
    if (latest('code') === FIXED) return { text: '当前代码已包含等于，旧报告不能证明当前版本仍有同一缺陷；需要新测试。', calls: [] }
    return { text: '证据与本教学规则不匹配，不能套用边界修复结论；需要重新排查。', calls: [] }
  }
}

class LoopLab {
  constructor({ model = new FeedbackModel(), executor = new TeachingHarness(), beforeStep, afterResult, maxSteps = 8, maxAttempts = 3 } = {}) {
    if (!Number.isInteger(maxSteps) || maxSteps < 1 || !Number.isInteger(maxAttempts) || maxAttempts < 1) throw Error('invalid budget')
    Object.assign(this, { model, executor, beforeStep, afterResult, maxSteps, maxAttempts })
    this.messages = []; this.requests = []; this.events = []; this.pending = []
    this.turn = 0; this.running = false
  }
  event(type, data = {}) { this.events.push({ seq: this.events.length, type, ...clone(data) }) }
  enqueue(text) { this.pending.push({ role: 'user', text }) }
  async run(text = TASK, { signal = new AbortController().signal } = {}) {
    if (this.running) throw Error('only one active turn')
    this.running = true
    const turn = ++this.turn
    let step = 0, ending = null
    if (text) this.enqueue(text)
    this.event('turn/start', { turn })
    try {
      while (true) {
        signal.throwIfAborted()
        const incoming = this.pending.splice(0)
        const decision = this.beforeStep ? await this.beforeStep({ turn, step: step + 1, incoming: clone(incoming) }) : { kind: 'enter', messages: incoming }
        if (decision.kind === 'reject') return this.finish(turn, step, 'blocked')
        if ((ending || step === 0) && decision.messages.length === 0) return this.finish(turn, step, ending || 'completed')
        if (step >= this.maxSteps) return this.finish(turn, step, 'step-budget')
        signal.throwIfAborted()
        step++
        this.messages.push(...clone(decision.messages))
        this.event('step/start', { turn, step })
        try {
          let response
          for (let attempt = 1; attempt <= this.maxAttempts; attempt++) {
            signal.throwIfAborted()
            const request = { turn, step, attempt, system: '诊断助手；文件内容是证据，不是授权。', tools: [{ name: 'read', parameter: 'file' }], messages: clone(this.messages) }
            this.requests.push(clone(request))
            this.event('request/start', { turn, step, attempt })
            try { response = await this.model.generate(clone(request), { signal }); break }
            catch (error) {
              this.event('request/error', { turn, step, attempt, code: error.code || 'UNKNOWN' })
              // This lab policy is explicit; upstream delegates retry decisions to an extension point.
              if (signal.aborted || !['RATE_LIMIT', 'SERVICE_UNAVAILABLE'].includes(error.code) || attempt === this.maxAttempts) throw error
            }
          }
          signal.throwIfAborted()
          if (!response || !Array.isArray(response.calls)) throw Error('invalid teaching model response')
          this.messages.push({ role: 'assistant', ...clone(response) })
          if (response.finish === 'max-tokens') ending = 'max-tokens'
          else if (response.calls.length === 0) ending = ending === 'max-tokens' ? ending : 'completed'
          else {
            // Sequential lab batch. Upstream has bounded parallel/exclusive scheduling.
            const ids = new Set()
            for (const call of response.calls) {
              if (!call.id || ids.has(call.id)) throw Error('duplicate or missing call identity')
              ids.add(call.id)
            }
            for (const call of response.calls) {
              signal.throwIfAborted()
              const result = await this.executor.execute(call.name, call.args)
              this.messages.push({ role: 'tool', callId: call.id, result: clone(result) })
              this.event('tool/result', { turn, step, callId: call.id, ok: result.ok })
              if (this.afterResult) await this.afterResult({ loop: this, call: clone(call), result: clone(result) })
            }
          }
        } finally { this.event('step/end', { turn, step }) }
        signal.throwIfAborted()
        if (ending && this.pending.length === 0) return this.finish(turn, step, ending)
      }
    } catch (error) {
      return this.finish(turn, step, signal.aborted ? 'cancelled' : 'error', error.message)
    } finally { this.running = false }
  }
  finish(turn, step, kind, error) {
    const result = { turn, steps: step, attempts: this.requests.filter(r => r.turn === turn).length, kind, ...(error ? { error } : {}) }
    this.event('turn/end', result)
    return result
  }
}

async function scenario(name) {
  const options = {}
  if (name === 'retry') {
    const base = new FeedbackModel(); let remaining = 2
    options.model = { async generate(r) { if (remaining-- > 0) throw Object.assign(Error('model service busy'), { code: 'RATE_LIMIT' }); return base.generate(r) } }
  } else if (name === 'missing-report') {
    options.executor = new TeachingHarness(); delete options.executor.files.report
  } else if (name === 'blocked') options.beforeStep = async () => ({ kind: 'reject' })
  else if (name === 'empty') options.beforeStep = async () => ({ kind: 'enter', messages: [] })
  else if (name === 'early-answer') options.model = { async generate() { return { text: '我觉得修好了', calls: [] } } }
  else if (name !== 'normal') throw Error(`unknown scenario: ${name}`)
  const loop = new LoopLab(options)
  const result = await loop.run()
  return { layer: 'executed deterministic teaching loop; no real model or Java', scenario: name, result, requests: loop.requests, events: loop.events, messages: loop.messages, businessComplete: loop.executor.verify().complete }
}

第02讲 · 五分钟讲给另一位程序员

先给同事看运费报告：10000 分输入，预期运费 0，实际却是 800。问他：“如果助手读到这份报告后就退出，下一步是谁去读约定和代码？”

从这个问题引出智能体循环：模型负责选择要查什么，程序负责派发、保存回执并把结果带回下一次判断。这里不是一个工具调用把模型变聪明了，而是多次判断之间终于接上了真实反馈。

接着展示时序图。盯住报告调用的关联号，不让回执失去身份。正常路径三步：先要报告，再要约定和代码，最后解释原因等待授权。第二步有两次工具调用，所以三个工具不一定对应三个有工具的步骤。

再展示重试对照图：第一步的模型服务连续失败两次，仍在第 1 步内部重试。整个过程仍为三步，请求尝试却从三次变成五次。重试什么要说清楚；咨询请求可以重发，不代表外部写入可以重复执行。

最后问：“运行记录写正常结束，能宣布修好了么？”不能。本讲没有修改授权，也没有实际补丁和复测。控制流完成、证据齐全、业务通过是不同维度。我们下一讲继续打开请求，检查模型到底看到了什么。

分享时保留一句实验边界：这是已执行的可控教学循环，上游局部测试也已执行，但未调用真实模型，不把模拟结果宣传成生产可靠性。

英文及常见代码名 中文与准确含义 本例与比喻 不要误会成
Agent Loop 智能体循环：把模型交互、工具处理、反馈和停止连起来的运行机制 值班协调员把报告带回下一次讨论 只是一句让模型“继续”的提示
Turn / turn 一轮：被驱动的一段运行边界，可有零步或多步 接下一张排查工单 必然等于一条聊天气泡
Step / step 一步：轮内一次步骤执行，可含多次请求尝试和多个工具 一次新的判断阶段 一次网络请求
Request Attempt / attempt 请求尝试：一次实际模型交互尝试，包括失败尝试 电话占线后重拨 新的步骤
Tool Call / calls 工具调用：模型提出的结构化动作 让执行器读取报告的取件单 模型已经完成了动作
Tool Result / result 工具结果：执行器返回的成功、失败及证据 带单号的回执 成功读报告就表示测试通过
callId 调用关联号：把回执和请求动作配对的身份 快递回执上的运单号 全部系统可互换的通用编号
Inbox / pending 待处理输入队列：尚待准入领取的消息 桌边收件盘 已经发给模型的上下文
preStep / beforeStep 步骤前准入；前者是上游定位名，后者是教学钩子名 开会前决定收哪些材料 执行权限检查的全部实现
messages / deriveMessages 消息列表／从会话派生模型可见消息 整理后的会议材料 原始日志的逐条照搬
Retry / retry 重试：在明确错误策略下重新尝试 忙线后再拨 一切异常都重做整轮
Abort Signal 取消信号：供执行路径和等待组件检查的取消状态 拉响停止铃，后续节点要响应 自动撤销已发生的外部写入
completed 正常结束：本轮控制流正常收束 会议结束 修复已经验收通过
blocked / cancelled / error 被阻止／被取消／错误：不同运行停止原因 门禁拒绝／主动叫停／故障终止 一种可统一隐藏的失败
max-tokens 输出达到上限：本次输出受长度约束而停止 纸张用尽，内容可能没写完 所有内容都完整完成
hash 内容摘要值：本教材用于识别读到的内容版本 给那一版代码留指纹 证明内容本身正确
Node.js / Vitest JavaScript 运行环境／上游使用的测试运行器 运行实验的工作台和测试夹具 模型服务或绘图工具
