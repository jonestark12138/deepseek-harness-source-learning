第二讲逐步讲解 · 跟着一张命令行订单读 TypeScript

源码快照：cd5ef8148158c3a752a658978873241fdf8e2bbc。代码链接均固定到该提交。

一、先回答最容易误会的一句

第一讲里“接到一个任务”在入口代码中先表现为一份参数。我们先看类型能帮助读者看见什么，再看它不会替运行时代码做什么。

很多 Java 工程师第一次看 TypeScript，会把类型想成 JVM（Java 虚拟机） 字节码里的运行时约束。更稳妥的第一印象是：类型主要服务于编译检查、编辑器提示和源码阅读；程序运行时执行的是 JavaScript。

像工作室收到的任务包裹，标签能提示“这份材料应该交给谁”，但不会替你打开报告或检查报告内容。同样，下面的 string 不会在运行时自动生成一段校验代码：

const collect = (value: string, previous: string[] = []): string[] =>
  [...previous, value]

这段来自 apps/cli/src/args.ts#L61。括号内的 value 和 previous 是参数名，各自冒号右边是类型；最后一个冒号后的 string[] 是返回类型。

边界要记牢：不是所有 TypeScript 语法都必然“零运行时影响”，例如某些 enum 或装饰器配置可能生成代码。本讲讨论的是仓库中常见的 interface、类型别名、类型注解和 import type。

二、函数签名就是收货与发货单

标签不会搬运材料，因此接下来要看实际接收订单的函数。先认输入输出，可以避免一进函数体就迷路。

看 parseDshArgs()：

export function parseDshArgs(
  argv: readonly string[],
  version: string,
): DshInvocation

先不读函数体，也能得到三条信息：

  • argv 是字符串只读数组；函数承诺不通过这个引用改数组。
  • version 是字符串。
  • 返回值属于 DshInvocation。

这很像 Java 的方法签名，但 readonly 是 TypeScript 对当前引用的编译期约束，不等于把数组在运行时深度冻结。函数签名是阅读入口，不是实现证明；输入检查、错误处理和副作用仍要看函数体与测试。

三、对象形状接口是对象验货单，不是 Java 类

返回类型只是名字；要知道返回的订单究竟装了什么，继续打开它对应的接口。

ProfileInvocation 写着：

interface ProfileInvocation {
  mode: 'profile'
  profile: string
  patches: string[]
  args: string[]
}

可以读成：“任何要被当作 ProfileInvocation 的值，都要符合这张验货单。” TypeScript 是结构类型系统：通常更关心形状是否满足，而不是对象是不是由名为 ProfileInvocation 的构造器创建。

mode: 'profile' 不是“任意字符串”，而是字符串字面量类型，只接受这个固定值。这里最关键，因为它把三张相似订单区分开。

与 Java interface 的重要区别：这个 TypeScript 接口本身没有运行时构造器、反射类对象或 instanceof 身份。它通常在编译后消失。

四、联合类型：不是三样都要，而是三选一

已经知道一张方案订单的形状，但入口还能接受别的命令。于是需要把几种允许的订单放在一起描述。

源码在 args.ts#L48：

export type DshInvocation =
  ProfileInvocation | DumpConfigInvocation | PluginInvocation

竖线读作“或”。一个 DshInvocation 在某一刻是三种形状中的一种，不是同时拥有三种形状的全部字段。

如果代码先判断：

if (invocation.mode === 'profile') {
  invocation.args
}

TypeScript 会根据 mode 缩小范围，知道分支内是 ProfileInvocation。这叫判别联合：

  • union（联合类型）本身是编译期概念；
  • mode 是普通对象字段，运行时真实存在；
  • if 或 switch 是 JavaScript 真的会执行的分支。

因此“类型被擦除”和“可以在运行时按模式字段分支”并不矛盾。运行时判断的是字段值，不是某个联合类型对象。

五、可选属性：问号不是 null（空值）的别名

分清订单类别以后，仍可能有没填的选项。现在检查字段缺省时，代码究竟补什么值。

BootOptions 中有：

interface BootOptions {
  patch?: string[]
  dumpConfig?: boolean
  dumpDefaultConfig?: boolean
}

patch? 表示属性可以不存在。仓库启用了 exactOptionalPropertyTypes，因此“没有这个属性”与“显式放入 undefined”会被更严格地区分。阅读时先问：调用者是否保证字段存在？源码里 options.patch ?? [] 正是在没有值时提供空数组。

六、异步：先拿取号单，再等结果

订单字段已经弄清，还不能把“调用启动函数”当成“已经启动完成”。这就需要读等待关系。

回到同一份命令行订单。入口的方案分支 在调用 runProfile() 前使用 await。这表明入口要等启动流程给出结果，再继续该分支，而不是拿到一个异步凭据就宣布工作台已经准备好。

可以把异步结果凭据理解成维修取件单：现在拿到单据，只说明结果将来会成功交付或失败，并不说明修好了。下面是只保留等待关系的教学片段，不替代原文件：

await runProfile({
  environment: loadLayeredEnv('dsh'),
  profile: invocation.profile,
  patchFiles: invocation.patches,
  args: invocation.args,
})

async 保证调用表达式得到异步结果凭据。Promise<void> 表示成功完成时没有业务结果值；不表示“同步返回 void（无业务结果）”。await 暂停当前异步函数后续语句的推进，事件循环仍可处理别的任务；它不是“新建一个线程”。

对源码阅读最有用的四个问题是：

  1. 异步结果凭据最终给什么类型？
  2. 哪些地方 await？
  3. 失败会在哪里抛出或转成拒绝？
  4. 调用者是否等待了它？

七、第一次跟读 args.ts（参数解析文件），只走四站

  1. 看 21–48 行：画出三张对象验货单和联合类型。
  2. 看 83–103 行：根据条件找两个返回分支。
  3. 看 112 行签名：确认输入与返回承诺。
  4. 搜索 resolved =：观察不同命令行解析器登记的命令动作如何产生联合类型成员。

不要第一次就钻进 Commander（命令行解析库）链式调用接口的每个方法。我们此刻只借这个文件练习“从签名和类型缩小阅读范围”。

八、合上源码后的准确表述

TypeScript 类型像源码上的标签与验货单：帮助我们在运行前发现不匹配，并让读者迅速判断输入、输出和可能分支。interface 描述对象形状；联合类型表达多种可能；字面量字段把分支区分开；异步函数通过异步结果凭据表达稍后完成。类型不是运行时校验器，源码中的真实字段、条件与异步操作才会在运行时发生。

第二讲练习与答案

先在纸上或脑中回答，再展开答案。

练习 1：读签名

function resolveBoot(program: Command, profile: string, options: BootOptions, args: string[]): DshInvocation

请说出四个输入和一个输出，并指出仅凭签名不能知道的两件事。

展开答案

输入依次是 Commander（命令行解析库）命令对象、装配方案字符串、BootOptions（启动选项类型） 形状、字符串数组；输出是 DshInvocation（命令解析结果类型） 联合类型。仅凭签名不知道函数会在哪些条件下报错，也不知道会返回联合类型中的哪一种；需要看函数体和测试。

练习 2：合法还是不合法

const x: DshInvocation = {
  mode: 'plugin',
  profile: 'tui',
  patches: [],
}
展开答案

不符合当前三种对象形状接口。PluginInvocation 需要 args，没有 patches；mode: 'plugin' 又排除了另外两种。注意这是编译期判断；若外部 JSON（结构化数据格式）未经运行时校验进入程序，类型声明本身不会拦截它。

练习 3：为什么模式字段有两份工作

展开答案

在运行时它是普通字符串字段，供 if/switch（条件分支） 分支读取；在编译期它是字面量判别字段，帮助 TypeScript 把联合类型缩小到某个成员。联合类型会擦除，字段不会因为参与类型判断就消失。

练习 4：异步结果凭据 是什么

判断：“返回 Promise<void> 等于函数立即返回 void，因此不需要等待异步结果。”

展开答案

错误。调用立即得到异步结果凭据；成功完成时异步结果凭据没有业务值。调用方是否必须等待异步结果取决于是否需要等待完成、捕获失败或保证顺序，不能把异步结果凭据丢掉后仍假设任务已经结束。

练习 5：源码定位

在固定提交的 apps/cli/src/args.ts 中找到：

  1. 三个判别字段值；
  2. 可选属性；
  3. readonly string[]；
  4. 一个返回对象字面量的分支。
展开答案

判别值是 profile、dump-config、plugin；BootOptions（启动选项类型） 三个字段可选；parseDshArgs 的 argv（参数字符串数组） 是只读字符串数组；resolveBoot 在 87 或 102 行附近返回对象字面量。行号只对应本讲固定提交。

练习 6：画图

只用四个物件画出 DshInvocation：一个入口、三个出口。箭头上写清楚它表示“按模式字段选择类型分支”，不要画成运行时调用链。

展开答案

关键不是美观，而是语义：入口标注联合类型；出口分别标注三种成员；分支条件是模式字段的三个字面量值；图注说明它既帮助编译器缩小类型，也对应运行时字段判断，但不表示每个分支都会依次执行。

第2讲术语与比喻词典

遇到陌生词，先回到这个问题：怎样从入口的一张订单看懂参数、分流和等待？ 以下是查阅页，正文会在需要时解释关键概念。英文只用于和源码对照；它不是额外的背诵任务。

英文与中文 直觉、实际职责与边界
TypeScript（带类型检查的 JavaScript 语言） 给代码添加编译期约束和提示；不是自动获得运行时输入校验。
interface（对象形状接口） 像验货单，说明对象需要哪些字段；本身不是运行时构造器。
union（联合类型） 几种允许形状选一种，不是所有字段全都具备。
narrowing（类型收窄） 根据已检查的条件排除不可能的类型，像按订单类别分流。
Promise（异步结果凭据） 像取件单，稍后可能成功也可能失败；拿到凭据不是已经完成。
async（异步函数标记） 使函数以异步结果凭据表达完成或失败；不承诺新建线程。
await（等待异步结果） 暂停当前异步函数后续推进，等待成功值或错误。
readonly（只读类型约束） 限制通过当前引用修改；不等于运行时深度冻结。
