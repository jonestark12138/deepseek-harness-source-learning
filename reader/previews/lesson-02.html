第二讲 · 把类型当成源码里的行李牌

源码快照：cd5ef8148158c3a752a658978873241fdf8e2bbc。本讲学习的是阅读 TypeScript 的最低必要语法，不是完整语言教程。

这一讲只追一个问题：类型怎样帮我们在代码真正运行前，看懂“会收到什么、可能返回什么、该沿哪条分支读”？

把 Java 的类型经验先带上，但不要一一硬套。TypeScript 的 interface、联合类型和类型注解更像贴在包裹上的行李牌：它们帮助编辑器和读者检查路线；包裹真正怎么移动，仍由 JavaScript 代码决定。

视觉课件

第二讲视觉课件 · 四张图读懂基础类型

先看图建立直觉，再用源码纠正比喻。类型系统不是运行时保安。

1. 类型是行李牌，不是发动机

类型告诉编辑器和读者“这里应当是什么”；真正运行的是编译后的 JavaScript。interface 和多数类型注解会被擦除，但像 mode 这样的普通字段会保留。

2. Interface 是验货单

interface 关心对象有没有这些字段、字段是什么类型。它不像 Java class 那样天然代表一个可实例化的运行时类。

3. 联合类型是一条有分拣码的传送带

DshInvocation 可以是三种形状之一。mode 是真实字段，也是类型系统用来缩小范围的判别码。

4. Async 像取号单

async function ...: Promise<T> 表示调用者先拿到 Promise；await 等的是成功值，异常则沿 Promise 拒绝路径传播。它不是新线程的同义词。

逐步讲解

第二讲逐步讲解 · 跟着一张命令行订单读 TypeScript

源码快照：cd5ef8148158c3a752a658978873241fdf8e2bbc。代码链接均固定到该提交。

一、先回答最容易误会的一句

很多 Java 工程师第一次看 TypeScript，会把类型想成 JVM 字节码里的运行时约束。更稳妥的第一印象是：类型主要服务于编译检查、编辑器提示和源码阅读；程序运行时执行的是 JavaScript。

像机场行李牌一样，标签可以让分拣员在装机前发现“这件行李不该去这里”。但标签不会自己把箱子搬上飞机。同样，下面的 string 不会在运行时自动生成一段校验代码：

const collect = (value: string, previous: string[] = []): string[] =>
  [...previous, value]

这段来自 apps/cli/src/args.ts#L61。名字左边是参数，冒号右边是类型；最后一个冒号后的 string[] 是返回类型。

边界要记牢：不是所有 TypeScript 语法都必然“零运行时影响”，例如某些 enum 或装饰器配置可能生成代码。本讲讨论的是仓库中常见的 interface、类型别名、类型注解和 import type。

二、函数签名就是收货与发货单

看 parseDshArgs()：

export function parseDshArgs(
  argv: readonly string[],
  version: string,
): DshInvocation

先不读函数体，也能得到三条信息：

  • argv 是字符串只读数组；函数承诺不通过这个引用改数组。
  • version 是字符串。
  • 返回值属于 DshInvocation。

这很像 Java 的方法签名，但 readonly 是 TypeScript 对当前引用的编译期约束，不等于把数组在运行时深度冻结。函数签名是阅读入口，不是实现证明；输入检查、错误处理和副作用仍要看函数体与测试。

三、Interface 是对象验货单，不是 Java class

ProfileInvocation 写着：

interface ProfileInvocation {
  mode: 'profile'
  profile: string
  patches: string[]
  args: string[]
}

可以读成：“任何要被当作 ProfileInvocation 的值，都要符合这张验货单。” TypeScript 是结构类型系统：通常更关心形状是否满足，而不是对象是不是由名为 ProfileInvocation 的构造器创建。

mode: 'profile' 不是“任意字符串”，而是字符串字面量类型，只接受这个固定值。这里最关键，因为它把三张相似订单区分开。

与 Java interface 的重要区别：这个 TypeScript interface 本身没有运行时构造器、反射类对象或 instanceof 身份。它通常在编译后消失。

四、联合类型：不是三样都要，而是三选一

源码在 args.ts#L48：

export type DshInvocation =
  ProfileInvocation | DumpConfigInvocation | PluginInvocation

竖线读作“或”。一个 DshInvocation 在某一刻是三种形状中的一种，不是同时拥有三种形状的全部字段。

如果代码先判断：

if (invocation.mode === 'profile') {
  invocation.args
}

TypeScript 会根据 mode 缩小范围，知道分支内是 ProfileInvocation。这叫判别联合：

  • 联合类型本身是编译期概念；
  • mode 是普通对象字段，运行时真实存在；
  • if 或 switch 是 JavaScript 真的会执行的分支。

因此“类型被擦除”和“可以在运行时按 mode 分支”并不矛盾。运行时判断的是字段值，不是某个联合类型对象。

五、可选属性：问号不是 null 的别名

BootOptions 中有：

interface BootOptions {
  patch?: string[]
  dumpConfig?: boolean
  dumpDefaultConfig?: boolean
}

patch? 表示属性可以不存在。仓库启用了 exactOptionalPropertyTypes，因此“没有这个属性”与“显式放入 undefined”会被更严格地区分。阅读时先问：调用者是否保证字段存在？源码里 options.patch ?? [] 正是在没有值时提供空数组。

六、Async：先拿取号单，再等结果

另一个小入口 packages/lsp/lsp-stdio/src/index.ts#L126 有：

export async function apply(ctx: Context, config: Config): Promise<void> {
  const entries = Object.entries(config.servers)
  // ...
  const providers = await (async () => { /* ... */ })()
}

async 保证调用表达式得到 Promise。Promise<void> 表示成功完成时没有业务结果值；不表示“同步返回 void”。await 暂停当前 async 函数后续语句的推进，事件循环仍可处理别的任务；它不是“新建一个线程”。

对源码阅读最有用的四个问题是：

  1. Promise 最终给什么类型？
  2. 哪些地方 await？
  3. 失败会在哪里抛出或转成拒绝？
  4. 调用者是否等待了它？

七、第一次跟读 args.ts，只走四站

  1. 看 21–48 行：画出三张对象验货单和联合类型。
  2. 看 83–103 行：根据条件找两个返回分支。
  3. 看 112 行签名：确认输入与返回承诺。
  4. 搜索 resolved =：观察不同 Commander action 如何产生联合类型成员。

不要第一次就钻进 Commander 链式 API 的每个方法。我们此刻只借这个文件练习“从签名和类型缩小阅读范围”。

八、合上源码后的准确表述

TypeScript 类型像源码上的标签与验货单：帮助我们在运行前发现不匹配，并让读者迅速判断输入、输出和可能分支。interface 描述对象形状；联合类型表达多种可能；字面量字段把分支区分开；async 函数通过 Promise 表达稍后完成。类型不是运行时校验器，源码中的真实字段、条件与异步操作才会在运行时发生。

练习与答案

第二讲练习与答案

先在纸上或脑中回答，再展开答案。

练习 1：读签名

function resolveBoot(program: Command, profile: string, options: BootOptions, args: string[]): DshInvocation

请说出四个输入和一个输出，并指出仅凭签名不能知道的两件事。

展开答案

输入依次是 Commander 命令对象、profile 字符串、BootOptions 形状、字符串数组；输出是 DshInvocation 联合类型。仅凭签名不知道函数会在哪些条件下报错，也不知道会返回联合类型中的哪一种；需要看函数体和测试。

练习 2：合法还是不合法

const x: DshInvocation = {
  mode: 'plugin',
  profile: 'tui',
  patches: [],
}
展开答案

不符合当前三种 interface。PluginInvocation 需要 args，没有 patches；mode: 'plugin' 又排除了另外两种。注意这是编译期判断；若外部 JSON 未经运行时校验进入程序，类型声明本身不会拦截它。

练习 3：为什么 mode 有两份工作

展开答案

在运行时它是普通字符串字段，供 if/switch 分支读取；在编译期它是字面量判别字段，帮助 TypeScript 把联合类型缩小到某个成员。联合类型会擦除，字段不会因为参与类型判断就消失。

练习 4：Promise 是什么

判断：“返回 Promise<void> 等于函数立即返回 void，因此不需要 await。”

展开答案

错误。调用立即得到 Promise；成功完成时 Promise 没有业务值。调用方是否必须 await 取决于是否需要等待完成、捕获失败或保证顺序，不能把 Promise 丢掉后仍假设任务已经结束。

练习 5：源码定位

在固定提交的 apps/cli/src/args.ts 中找到：

  1. 三个判别字段值；
  2. 可选属性；
  3. readonly string[]；
  4. 一个返回对象字面量的分支。
展开答案

判别值是 profile、dump-config、plugin；BootOptions 三个字段可选；parseDshArgs 的 argv 是只读字符串数组；resolveBoot 在 87 或 102 行附近返回对象字面量。行号只对应本讲固定提交。

练习 6：画图

只用四个物件画出 DshInvocation：一个入口、三个出口。箭头上写清楚它表示“按 mode 选择类型分支”，不要画成运行时调用链。

展开答案

关键不是美观，而是语义：入口标注联合类型；出口分别标注三种成员；分支条件是 mode 的三个字面量值；图注说明它既帮助编译器缩小类型，也对应运行时字段判断，但不表示每个分支都会依次执行。

分享稿

第二讲分享稿 · 五分钟讲清 TypeScript 类型

我把 TypeScript 类型理解成包裹上的行李牌，而不是搬运行李的发动机。

第一，函数签名是收货与发货单。parseDshArgs(argv: readonly string[], version: string): DshInvocation 已经告诉我输入和输出的大致形状，让我不用先读两百行函数体。

第二，interface 是对象验货单。它描述字段，而不是天然生成一个 Java 式运行时类。ProfileInvocation 要求 mode、profile、patches 和 args。

第三，联合类型表示多种可能中的一种。DshInvocation 是三种 invocation 的联合，mode 像分拣码。TypeScript 用它缩小类型，JavaScript 在运行时也能读取这个真实字段。

第四，async 函数给调用者 Promise。Promise<void> 不是立即返回 void；它表示稍后完成，但没有业务返回值。await 也不是新线程的同义词。

最重要的边界是：类型能帮助检查和阅读，却不会自动替代运行时验证。看到一个外部 JSON 标成某个 interface，不等于它已经被真实校验。

源码练习只需走两处：先读 apps/cli/src/args.ts，再看一个 async apply()。
