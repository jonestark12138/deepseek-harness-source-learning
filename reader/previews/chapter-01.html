逐步讲解

第01讲 · 先别猜：从一条失败断言开始

源码基线：cd5ef8148158c3a752a658978873241fdf8e2bbc。业务案例为虚构 Java 运费服务；图与流程是教学推演，源码事实另有固定证据。

一、先把一件小事说具体

你维护一个 Java 运费服务。业务约定是“满 100 元免运费，不满收 8 元”。金额以分存储，避免把本讲变成小数精度课。今天有人只发来一句话：“恰好 100 元的测试失败了，先帮我查原因，不要修改。”

这句话没有告诉助手失败的实际值，也没有给实现。此时直接回答“把大于改成大于等于”可能恰好猜对，却还不是排查。也可能是测试预期错、输入单位错，或者执行的是旧版本。第一条规则是：猜想可以提出，事实必须通过材料取得。

Model（模型）负责根据输入推理和生成内容，像坐在桌前分析材料的人。Agent Harness（智能体运行支撑）负责把材料放上桌、安排受控动作、保存过程并决定怎样继续。Agent（智能体）在本书概览中指这套能围绕任务行动的整体；源码中的同名接口另有更窄的职责，不能把教学等式当作接口定义。

三格为同一运费任务的教学状态变化或故障对照。图不是实际运行日志；关键区别见各格说明。

二、同一张报告，会怎样缩小猜测范围

第一次读取报告，得到下面的教学预期输出。它是本书固定夹具的预期，不是假装运行过真实模型的日志：

amount=10000 expected=0 actual=800 FAIL

现在能确认的只有：该测试给出 10000 分，期望免运费，却收到 800 分。你仍然不知道实现是不是严格大于。下一次需要读业务约定和相关代码，不是把这条报告反复换一种说法。

我们把这份证据称为“失败报告”。整部教材不换另一个数据库或旅游案例：后面的日志、工具、恢复、摘要、分工，都围绕这项排查增加条件。

三、报告与实现终于对上了

读取 ShippingCase.java 后，本书夹具中的核心实现是：

static int shippingFee(int orderCents) {
    if (orderCents < 0) throw new IllegalArgumentException("negative amount");
    return orderCents > 10000 ? 0 : 800;
}

把 10000 代进去，严格大于条件为假，返回 800；业务约定却包含“等于”这个边界。因此原因不是“模型感觉像边界问题”，而是约定包含等于，实现排除了等于，报告正好在这个输入上失败。三份材料互相支持，才形成解释。

这种读法与你排查 Java 服务一致：报错是线索，不是原因；代码是实现，不一定符合业务；测试是一个可重复观察，不自动证明所有情况。

四、会修复，为什么还要停一下

用户说的是先查原因。修改文件是新的动作，不能因为原因明显就自动获得许可。Tool（工具）是系统提供的一种动作入口，例如读文件、编辑文件或运行测试；模型生成工具请求，真正的执行由运行支撑完成。

因此第一阶段的正确交付是报告原因、证据和建议改动，然后等待修改授权。拿到“只修边界判断，保留测试”的明确许可后，才把返回行改成：

return orderCents >= 10000 ? 0 : 800;

这个改动很小，许可范围也很小。它不授权删除失败测试、升级所有依赖，或修改无关业务。系统执行侧还可能拒绝操作；“用户允许”和“本次工具真的执行成功”也要分开记录。

五、改了文件，还没有到终点

最后重新测试阈值附近三个输入：

金额（分） 预期运费（分） 这项检查排除什么
9999 800 不能为了免运费把所有情况都改成零
10000 0 修复本次边界失败
10001 0 不破坏原来已正确的高于阈值分支

没有新测试结果，就只能说“已修改，待验证”。报告通过后，还要确认测试针对当前文件、退出码成功、测试预期没被偷偷改掉。全书最终交付沿用这组标准。

六、回到运行支撑源码：谁让过程继续

上面的业务服务是虚构夹具，下面的运行机制才来自固定的 DeepSeek Harness 源码。循环驱动检查模型回复中有没有工具调用；没有工具调用可以返回本轮完成状态，有工具调用则执行并根据结果决定是否继续。注意源码允许工具批次明确结束，不能把“调用工具后必然无限继续”当规则。

以下是固定提交中的定位片段（连续原文；中文说明放在代码之外）：

      if (finish.kind === 'max-tokens') return { kind: 'max-tokens' }

      const toolCalls = message.content.filter(block => block.type === 'tool-call')
      if (toolCalls.length === 0) return { kind: 'completed' }
      const { concluded } = await executeToolCalls(
        this.loopCtx, turn, step, toolCalls, signal,
        context => this.inbox.splice('next-step', this.inbox.nextStep.length, 0, [context]),
      )
      return concluded ? { kind: 'completed' } : null

这段先看三个位置：过滤工具调用、执行调用、根据返回状态结束或继续。报告不在模型脑中自动出现，文件也不会因模型说“已修改”而变化。本讲只建立闭环；第二讲就沿“读完报告，还欠一次读代码”拆开这个继续机制。

词典用于回查，正文在首次使用处解释。代码、参数与路径保留原拼写；产品名称不逐字翻译。模型上下文和插件上下文不是一回事。

Model（模型）

根据本次收到的材料推理并生成回答或动作请求，像分析桌前证据的工程师。磁盘上的报告没有送进请求时，它并不知道报告内容；生成修改建议也不会直接改文件。

Agent Harness（智能体运行支撑）

围绕模型组织输入、动作执行、状态与继续规则的运行支撑，像配有资料台、工具和记录员的工作室。它不是另一个更聪明的大脑，也不只是一份工具清单。

Agent（智能体）

本书概览指模型与运行支撑共同组成的任务执行整体。像有资料、工具与协作规则的排障小组；上游同名类型的职责可能更窄，不能据教学等式推导接口。

Tool（工具）

Tool（工具）是系统提供的一种动作入口，例如读文件、编辑文件或运行测试；模型生成工具请求，真正的执行由运行支撑完成。
