二、第一站：README（包说明文档）先建立假说

带着这个问题，先从作者的职责说明得到待验证假说。

会话 README（包说明文档）的 Summary 给出一组强主张：

  • Session（会话）是 append-only（仅追加）事件日志；
  • 日志是模型可见事实的单一来源；
  • 大语言模型消息由 deriveMessages() 派生，不另外保存；
  • 内存存储暴露为 ctx.sessions；
  • 持久化由独立后端实现监听事件并响应持久化等待；
  • 这个包本身不发起模型调用。

先把它们写成“待核对假说”，而不是立即当成最终事实。README（包说明文档）的源码导航还告诉我们关键入口在 src/index.ts，投影逻辑在 src/surface.ts，JSON（结构化数据格式）边界在 src/json.ts。

四、第三、四站：入口和实现验证核心机器

入口已经找到，现在只核对与测试证据有关的三件事：怎样写入、怎样取出、何时算保存完成。

src/index.ts 既导出会话相关类型与辅助函数，也实现 Session 和 SessionStore。先围绕 README（包说明文档）的核心主张寻找最小证据。

1. 日志是否真是仅追加

Session 内部有 private log: SessionEvent[] = []。

append() 的顺序是：

  1. 快照并验证 JSON（结构化数据格式）；
  2. 建立 seq = log.length 的冻结事件；
  3. 让 surface（消息投影结构）预先验证；
  4. log.push(event)；
  5. 通知观察者并返回事件。

这支持“追加日志”的说法，而且异常会尽量在进入日志之前暴露。

2. 模型消息是否另存一份

deriveMessages() 遍历消息投影结构节点，把对应事件投影成消息，并缓存已处理位置；每次返回一个新数组，里面复用被冻结的消息对象。

因此模型历史不是与日志并列维护的第二份真相，而是可重建投影。消息投影结构替换会改变未来投影，却不删除原始日志事件。

3. 生命周期和持久化在哪里

SessionStore 继承 Cordis Service。普通 create() 把会话的清理责任绑定到调用它的插件安装实例。这里先理解成“谁创建，就登记在谁的资源账下”；第六讲再展开副作用登记机制。

flush() 收集持久化完成约定监听器，等待所有监听器结束；若有失败，再抛出首个失败。它负责“等待落盘屏障”，却不在本包中实现磁盘后端。

五、第五站：测试钉住边界

实现看上去合理，还需要异常测试帮我们确定边界，尤其不能让外部修改悄悄改写旧证据。

测试文件很大，不要顺序通读。围绕主张用测试名搜索：

  • derives message history from the event log：验证派生消息；
  • isolates the log from mutation：验证外部不能借派生对象改写日志；
  • rejects non-JSON-serializable event data：验证失败发生在源头；
  • snapshots append data：验证调用者随后改原对象也不会改日志。

这些测试把“仅追加”从一句设计口号拆成可观察约束：连续序号、输入快照、深冻结、拒绝不可持久化数据。

六、第六站：反向找真实调用方

测试说明局部行为，仍没有回答模型在哪儿使用它。最后反向找真正的调用者，才能回到第一讲的任务。

现在从 append(、deriveMessages( 反向搜索。agent-loop/src/agent.ts#L252-L330 在一轮处理和一步模型交互边界追加事件，也把用户消息写入会话。

随后 agent.ts#L339-L366 在构建模型请求时调用 session.deriveMessages()。

这形成闭环：智能体循环驱动把发生的事情写入会话，又从同一会话派生模型要看的消息。模型调用发生在循环驱动的大语言模型边界，不在会话包里。

八、把方法迁移到任意代码包

每读一个包，只写三类句子：

  • 已确认：有实现、测试或调用方证据；
  • 合理推断：多份证据一致，但还没走到关键分支；
  • 仍未验证：性能、并发、异常恢复或平台差异尚未检查。

这会阻止“看见名字就猜职责”和“看见依赖就猜调用”两种常见错误。

练习 4：持久化边界

展开答案

不是。它收集并等待持久化完成约定监听器，相当于发起并等待持久化屏障；具体后端由独立持久化代码包提供。

练习 5：真实主链

“追加”和“派生”：循环驱动把一轮处理、一步模型交互、消息等事件追加到会话；构建模型请求时从同一会话 deriveMessages（消息派生方法）。

第5讲术语与比喻词典

遇到陌生词，先回到这个问题：第一次读到的测试报告，怎样成为下一次模型判断的材料？ 以下是查阅页，正文会在需要时解释关键概念。英文只用于和源码对照；它不是额外的背诵任务。

英文与中文 直觉、实际职责与边界
Session（会话） 像可追加工作日志，记录事实并提供供模型使用的派生内容。
append-only（仅追加） 新事实向后写入，不因展示方式改变就抹掉原始记录。

SessionStore（会话存储服务） 管理内存中的会话及生命周期，不等于具体磁盘数据库。
durability（持久可靠性） 让记录在进程结束后仍可保存的要求；需要后端执行，不能只靠内存存在。
flush（等待持久化屏障） 等待相关持久化参与者完成；失败必须传播，不能当作保存保证。
