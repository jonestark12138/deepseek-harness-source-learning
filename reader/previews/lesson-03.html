第三讲 · 让类型成为架构的防错工装

源码快照：cd5ef8148158c3a752a658978873241fdf8e2bbc。第二讲先学会看标签，本讲再看大型工程为什么需要更高级的类型工具。

这一讲只追一个问题：泛型、声明合并、品牌类型和 ESM 写法，为什么会反复出现在 Harness 这类架构代码中？

主比喻是一间有标准夹具、扩展登记册和门禁工牌的工作室：泛型保持“放进去什么、取出来还是什么”的关系；声明合并让插件把自己的栏位登记到共同目录；品牌类型给外形相同的字符串加上不可混用的工牌；satisfies never 检查分支清单有没有漏项。

视觉课件

第三讲视觉课件 · 五种架构型语法

1. 泛型是可调尺寸的标准夹具

K extends keyof Events 不是“任何 K”，而是事件名集合中的某一个 K；参数和返回值继续跟着这个 K 关联。

2. 声明合并是扩展登记册

declare module 让 TypeScript 知道 ctx 多了什么；真正的运行时提供还要有服务构造与注册代码。

3. 品牌类型是同形工牌

SessionId、WorkspaceId 都是字符串，却在编译期不应互换。序列化时仍是普通字符串。

4. satisfies never 是关门前点名

当联合类型已经被所有 case 排除，default 中理应只剩 never；未来新增成员会让编译失败，提醒补分支。

5. ESM 导入像货架地址

本仓库允许源码写 .ts 相对导入，并配置输出重写。import type 只带来类型依赖；具体行为取决于项目 tsconfig 和构建链。

逐步讲解

第三讲逐步讲解 · 类型不只是标签，还是防错工装

源码快照：cd5ef8148158c3a752a658978873241fdf8e2bbc。

第二讲把类型当成行李牌。本讲向前一步：大型插件系统里，类型还要表达“哪个事件配哪些参数”“哪个插件给 Context 增加什么”“哪些字符串虽然长得一样却不能混用”。

一、泛型：保存对应关系，不是把类型变模糊

Java 工程师可以先把 <T> 理解成“给类型留一个参数位”，但 TypeScript 泛型常与 keyof、索引访问一起使用。Cordis 的事件方法就是好例子：

emit<K extends keyof Events>(
  name: K,
  ...args: Parameters<Events[K]>
): void

证据在 vendor/cordis/src/events.ts#L34-L63。逐段翻译：

  • keyof Events 是 Events 所有键名组成的集合；
  • K extends ... 表示本次调用的 K 必须来自这个集合；
  • Events[K] 取出该事件名对应的监听函数类型；
  • Parameters<...> 再取出它的参数元组。

泛型在这里像可调尺寸的夹具：选定事件名后，参数槽位跟着调整。若只写成 name: string, ...args: any[]，语法更短，却丢失了事件名与参数之间的对应关系。

边界：这些泛型约束主要在编译期工作，不能替代运行时收到陌生事件名时的防御。

二、声明合并：给共同目录加一栏

Cordis 的 Context 是插件共享服务入口。Workspace 包中出现：

declare module '@deepseek-ai/cordis' {
  interface Context {
    workspaceRegistry: WorkspaceRegistry
  }
}

见 packages/workspace/workspace/src/index.ts#L67-L71。

这叫模块扩展（module augmentation）：它告诉 TypeScript，“当你看 @deepseek-ai/cordis 的 Context 时，还要把这一栏合进去。”多个插件可以各自扩展同一个接口，读者仍能得到统一的 ctx.xxx 提示。

但登记册不是设备本身。运行时还需要真实的 WorkspaceRegistry 服务被创建、提供并满足生命周期。只有 declare module，不会凭空出现 ctx.workspaceRegistry。

它和 Java 的感觉类似于多个模块共同丰富一份编译期契约，但机制不是修改某个已编译 class，也不是 Spring Bean 自动注册。

三、import type：只借说明书，不搬设备

同一个文件顶部既有普通 import，也有 type-only import：

import { Context, Service } from '@deepseek-ai/cordis'
import type { SessionHeader, SessionId } from '@deepseek-ai/dsh-session'
import type {} from '@deepseek-ai/dsh-session-persistence'

见 workspace/src/index.ts#L8-L16。

import type { X } 明确 X 只用于类型位置，发出的 JavaScript 不需要这条值导入。import type {} 则常用于引入声明扩展：它让 TypeScript 看见另一个模块提供的类型补充，却不制造运行时 import。

注意：这解释的是编译产物依赖，不等于“被提到的包在系统架构上没有运行时角色”。它可能由其他配置或插件路径在运行时加载。

四、品牌类型：给相同字符串发不同工牌

packages/util/brand/src/index.ts#L24-L27 定义：

declare const BRAND: unique symbol
export type Branded<B extends string> =
  string & { readonly [BRAND]: B }

随后 Workspace 声明：

export type WorkspaceId = Branded<'WorkspaceId'>

于是 WorkspaceId 仍能像字符串一样记录、比较和序列化，但类型系统会把它与 SessionId 等其他品牌区分开。构造函数 WorkspaceId(id: string) 内部只是断言，源码注释明确说运行时仍是同一个字符串。

为什么有用？结构类型系统通常认为形状相同就兼容；跨 package 的多个 ID 都是 string，最容易传错。品牌像不同颜色门禁工牌，弥补“外形相同却语义不同”的缺口。

边界：品牌不验证字符串格式，也阻止不了 as WorkspaceId 的强制断言。它是编译期防误接，不是密码学或运行时权限。

五、satisfies never：新状态来了，旧 switch 必须报警

stopReasonError() 处理 completed、cancelled、error 后，在 default 写：

result.stopReason satisfies never

如果前三个 case 已穷尽联合类型，default 分支中的值理论上不可能存在，类型应缩小成 never。未来有人新增 timed-out 却没补 case，编译器会在这里报错。

这像关门前点名：不是说意外永远不会发生，而是把“新增一种合法状态却忘记处理”的维护错误变成编译失败。源码仍保留 defensive default，因此面对异常运行时值还会生成错误描述。

六、.ts 相对导入：地址写法由整个构建约定决定

仓库源码常写：

import { WorkspaceEntity } from './entity.ts'

根 tsconfig.base.json#L6-L18 同时设置：

  • module: esnext
  • moduleResolution: bundler
  • allowImportingTsExtensions: true
  • rewriteRelativeImportExtensions: true

因此在这个仓库里，源码可以明确写 .ts，编译输出会重写相对扩展名。它改善源码定位，也让 import 与真实源文件对应。

不要把它复制成“所有 Node ESM 都应该这样写”。能否写 .ts、运行器是否直接执行 TypeScript、输出要变成 .js 还是由 bundler 接管，都取决于项目配置和工具链。

七、四站源码路线

  1. vendor/cordis/src/events.ts：只看 K extends keyof Events 与 Parameters<Events[K]>。
  2. packages/workspace/workspace/src/index.ts：找 import type、declare module 和 WorkspaceId()。
  3. packages/util/brand/src/index.ts：看品牌原语为什么没有运行时代码。
  4. tsconfig.base.json：把 .ts 导入放回编译配置解释。

看到 Cordis 具体事件实现先停下；那是第八讲。此刻目标是读懂类型在表达哪些架构关系。

八、一句话总结

泛型守住“名称与参数”的对应关系；声明合并让插件扩展共同契约；品牌类型阻止同形 ID 混用；satisfies never 守住状态分支的完整性；ESM 导入写法则由仓库的编译约定保证。它们都是防错工装，不是运行时能力本身。

练习与答案

第三讲练习与答案

练习 1：泛型保住了什么

为什么 emit<K extends keyof Events>(name: K, ...args: Parameters<Events[K]>) 比 emit(name: string, ...args: any[]) 更有用？

展开答案

前者把事件名限制在 Events 的键内，并根据具体事件名推出对应参数；后者允许任何名字和任何参数，丢掉了关系。两者仍都需要真实的运行时分发实现。

练习 2：只有 declare module 会怎样

假设插件只写 declare module 增加 ctx.demo，却没有任何 provider 或初始化代码。运行时会自动出现 demo 吗？

展开答案

不会。声明扩展只改变编译器看到的类型形状。运行时属性要由真正的服务注册或对象赋值产生；否则访问可能得到 undefined 或触发框架错误。

练习 3：品牌能防什么、不能防什么

展开答案

能在正常类型检查下防止 WorkspaceId 与其他 string 品牌混用；不能校验 UUID 格式、提供运行时权限或阻止开发者强制类型断言。序列化后仍是普通字符串，边界输入需要重新验证和建立品牌。

练习 4：新增状态

若 WorkflowStopReason 新增 timed-out，但 switch 没有 case，会发生什么？

展开答案

在开启类型检查时，default 中 result.stopReason satisfies never 将不再成立，编译失败，提醒补上分支。若异常值绕过类型系统进入运行时，defensive default 仍会返回异常描述。

练习 5：import type 的误区

判断：“使用 import type {} 就证明这个 package 在整个系统运行时完全没用。”

展开答案

错误。它只说明当前 import 不生成值依赖。该 package 可能通过配置、别的值 import 或插件加载器参与运行。

分享稿

第三讲分享稿 · 类型系统如何替架构守门

第二讲说类型像标签，第三讲我会说它还是一套防错工装。

泛型像可调夹具。Cordis 的事件方法用事件名 K 找到对应参数，因此不会把 A 事件的参数接到 B 事件上。

声明合并像扩展登记册。每个插件都能告诉 TypeScript 自己给 Context 增加了哪一栏，但登记不会自动创造运行时服务。

品牌类型像同形工牌。WorkspaceId 和 SessionId 运行时都是字符串，编译期却不能随手互换。它降低跨 package 接错 ID 的风险，不负责校验格式或权限。

satisfies never 像关门前点名。联合类型出现新状态而 switch 漏处理时，让维护错误在编译阶段暴露。

最后，源码里的 .ts 相对导入不是通用魔法；本仓库用 allowImportingTsExtensions 和 rewriteRelativeImportExtensions 形成完整构建约定。读架构代码时，类型与 tsconfig 要放在一起看。

术语词典

第三讲术语与比喻词典

英文 / 语法 先这样理解 技术含义 比喻边界
Generic 泛型 可调夹具 用类型参数保存输入输出之间的关系 通常不会自动生成运行时验证
extends 约束 夹具尺寸范围 限制类型参数必须满足某集合或形状 不是 class 继承的唯一含义
keyof 目录的所有栏名 取得对象类型的键联合 不枚举运行时对象
Indexed access T[K] 按栏名取说明 从类型 T 取得键 K 对应的类型 不等于运行时读取表达式
Module augmentation 模块扩展 扩展登记册 declare module 合并已有模块声明 不会创建运行时服务
import type 只借说明书 只导入类型，避免发出值 import 不代表目标包没有架构作用
Brand / branded type 品牌类型 同形工牌 用 unique symbol 交叉类型区分同底层值 不验证格式、不提供权限
unique symbol 不可仿造的印章位 类型层面唯一的 symbol 身份 本例的 BRAND 只用于类型
never 不该有任何值 不可能发生的类型 运行时仍可能遇到绕过类型的异常值
satisfies never 关门点名 验证当前值已被分支穷尽 不替代 defensive runtime handling
ESM 标准模块货架 JavaScript 的 import/export 模块体系 具体解析规则取决于环境与工具链
.ts relative import 源码货架地址 相对导入明确指向 TypeScript 源文件 需要仓库编译配置支持
